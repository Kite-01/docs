You can run Kite from source with Bun, or as a Docker image. Either way you need a Postgres database.

## Requirements

- [Bun](https://bun.sh) 1.4 or newer, if you run from source
- PostgreSQL (Kite is tested against Postgres 18)
- A public URL for the server, so providers can tell it about deposits (`http://localhost:3000` is fine while you try it)
- A wallet mnemonic for the operator, and a little of each chain's native token in it for gas, unless you use a [gas sponsor](/server/providers/)

## From source

<Steps>

1. **Get the code**

   ```sh
   git clone https://github.com/Kite-01/server kite
   cd kite
   bun install
   bun install --cwd client
   ```

2. **Start Postgres**, if you don't have one. This matches the example configuration:

   ```sh
   docker run -d --name kite-db -p 54320:5432 \
     -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=kite postgres:18
   ```

3. **Configure it.** Copy the example and fill it in; [Configuration](/server/configuration/) explains every variable.

   ```sh
   cp .env.example .env
   ```

   At minimum, replace `KITE_ENCRYPTION_KEY`, `KITE_OPERATOR_MNEMONIC` and `KITE_ROOT_KEY` with your own values.

4. **Create the tables**

   ```sh
   bun run migrate
   ```

5. **Run it**

   <Tabs>
     <TabItem label="Development">
       ```sh bun run dev ``` The API and dashboard reload as you change the
       code.
     </TabItem>
     <TabItem label="Production">
       ```sh bun run build bun run start ``` `build` typechecks and builds the
       dashboard into `client/dist`, which the server serves.
     </TabItem>
   </Tabs>

6. **Open the dashboard** at the URL it prints, usually `http://localhost:3000`, and sign in with your root key. Then follow [First run](/server/first-run/).

</Steps>

<Aside type="caution">
  Use `bun run migrate`, not `bun run db:migrate`. Besides applying the
  migrations, `migrate` runs the data upgrades some releases need.
</Aside>

## With Docker

The repository's Dockerfile builds the dashboard and the server into one image. It runs migrations every time it starts.

```sh
docker build -t kite-server .
docker run -d --name kite -p 3000:3000 --env-file .env kite-server
```

From inside a container, `localhost` is the container itself: point `KITE_PG_DB_URL` at your database's real host, or run both on one Docker network.

## Check it's up

```sh
curl -s http://localhost:3000/api/overview/info -H "x-kite-root-key: $KITE_ROOT_KEY"
```

```json
{
  "version": "1.0.0",
  "operators": [{ "chainType": "Evm", "address": "0x…" }],
  "chains": []
}
```

The operator address is the wallet that will send settlement and refund transactions. Fund it with gas on each chain you enable, unless a gas sponsor pays for it.
