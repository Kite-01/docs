Kite reads its settings from environment variables, or from a `.env` file in the directory it starts in. It checks them all at startup and refuses to start, naming the problem, if any is missing or invalid.

| Variable                          | Required | Default  | Description                                                                                                  |
| --------------------------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| `KITE_PUBLIC_BASE_URL`            | yes      |          | The public URL of this server. Providers send deposit callbacks to it, and checkout links are built from it. |
| `KITE_PG_DB_URL`                  | yes      |          | Postgres connection URL, such as `postgres://user:password@host:5432/kite`.                                  |
| `KITE_PG_DB_CERTIFICATE`          | no       |          | CA certificate, in PEM, to verify Postgres over TLS. See [Managed Postgres](#managed-postgres).              |
| `KITE_PG_POOL_MAX`                | no       | `10`     | Most connections the server holds for its queries.                                                           |
| `KITE_PG_BOSS_POOL_MAX`           | no       | `20`     | Most connections the job queue holds, plus one it keeps for notifications.                                   |
| `KITE_ENCRYPTION_KEY`             | yes      |          | 32 random bytes, base64. Encrypts provider keys and webhook secrets at rest.                                 |
| `KITE_OPERATOR_MNEMONIC`          | yes      |          | BIP-39 mnemonic of the operator wallet, which settles and refunds transfers.                                 |
| `KITE_ROOT_KEY`                   | yes      |          | At least 16 characters. Signs you into the dashboard and grants full API access.                             |
| `KITE_PORT`                       | no       | `3000`   | Port to listen on.                                                                                           |
| `KITE_ENABLE_DASHBOARD`           | no       | `true`   | Serve the dashboard. The checkout at `/pay` is served either way.                                            |
| `KITE_ENABLE_OPENAPI_UI_SPECS`    | no       | `true`   | Serve the interactive API docs at `/openapi` and the spec at `/openapi/json`.                                |
| `KITE_ENABLE_OPENAPI_UI_PROVIDER` | no       | `scalar` | `scalar` or `swagger`.                                                                                       |
| `KITE_IS_TESTNET`                 | no       | `false`  | Run on testnets instead of mainnets. See [Testnets](/server/testnets).                                       |

## Managed Postgres

Hosted databases usually require TLS and allow few connections.

- **TLS**: set `KITE_PG_DB_CERTIFICATE` to your provider's CA certificate, such as Aiven's `ca.pem`, and leave `sslmode` out of `KITE_PG_DB_URL`. Kite then verifies the database against that certificate. Without the variable, the URL's `sslmode` decides. Where a host only takes one-line values, write the certificate's line breaks as `\n`.
- **Connections**: each running server holds up to `KITE_PG_POOL_MAX + KITE_PG_BOSS_POOL_MAX + 1` connections, and while a deploy replaces it, the old and new servers run together for a moment. Size the pools so twice that fits under your database's limit. With a limit of 20, for example, set both to `3`. Queries and jobs wait for a free connection rather than fail.

## Generating secrets

```sh
# KITE_ENCRYPTION_KEY
openssl rand -base64 32

# KITE_ROOT_KEY
openssl rand -base64 48
```

For the mnemonic, create a new wallet just for Kite with any wallet that shows its recovery phrase, and use it for nothing else.

## Keep these safe

- **`KITE_ENCRYPTION_KEY`**: lose it and the server can't read the provider keys and webhook secrets it stored. Changing it has the same effect.
- **`KITE_OPERATOR_MNEMONIC`**: it controls the operator wallet, which can settle, refund and recover every transfer's funds.
- **`KITE_ROOT_KEY`**: anyone with it can do anything through the API. Use [API keys](/authentication/api-keys) for your applications instead.

## Not environment variables

Provider keys are set from the dashboard's **Providers** page and stored encrypted in the database. See [Providers](/server/providers).
