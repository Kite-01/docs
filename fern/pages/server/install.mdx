---
title: Install
description: Get a Kite server running locally or on a machine of your own.
---

The quickest way is the published Docker image, `ghcr.io/kite-01/server`, with a Postgres of its own. You can also run Kite from source with Bun.

## Requirements

- [Docker](https://docs.docker.com/get-docker/) with Compose, or [Bun](https://bun.sh) 1.4 or newer to run from source
- PostgreSQL (Kite is tested against Postgres 18)
- A public URL for the server, so providers can tell it about deposits (`http://localhost:3000` is fine while you try it)
- A wallet mnemonic for the operator
- Optionally, keys for a [deposit notifier and a gas sponsor](/server/providers)

## With Docker

<Steps>

<Step title="Get the compose file and the example configuration">

```sh
mkdir kite && cd kite
curl -fsSLO https://raw.githubusercontent.com/Kite-01/server/main/docker-compose.yml
curl -fsSL -o .env https://raw.githubusercontent.com/Kite-01/server/main/.env.example
```

`docker-compose.yml` runs the image and a Postgres for it, with its data in a Docker volume.

</Step>

<Step title="Configure it">

In `.env`, replace `KITE_ENCRYPTION_KEY` (`openssl rand -base64 32`), `KITE_OPERATOR_MNEMONIC` and `KITE_ROOT_KEY` with your own values. [Configuration](/server/configuration) explains every variable. The compose file sets the database URL itself.

</Step>

<Step title="Run it">

```sh
docker compose up -d
```

The image runs its migrations, then serves the API, the dashboard and the checkout on port 3000.

</Step>

<Step title="Open the dashboard">

Open `http://localhost:3000` and sign in with your root key. Then follow [First run](/server/first-run).

</Step>

</Steps>

### Image tags

| Tag         | Follows    | Use it for                                                    |
| ----------- | ---------- | ------------------------------------------------------------- |
| `latest`    | `main`     | mainnets                                                      |
| `testnet`   | `testnet`  | [testnets](/server/testnets): also set `KITE_IS_TESTNET=true` |
| `sha-<sha>` | one commit | pinning an exact build                                        |

Choose one with `KITE_IMAGE`, for example `KITE_IMAGE=testnet docker compose up -d`. To update, `docker compose pull && docker compose up -d`. The image is built for `linux/amd64` and `linux/arm64`.

To run the image against a database you already have, without the compose file:

```sh
docker run -d --name kite -p 3000:3000 --env-file .env ghcr.io/kite-01/server:latest
```

From inside a container, `localhost` is the container itself: point `KITE_PG_DB_URL` at your database's real host.

## From source

<Steps>

<Step title="Get the code">

```sh
git clone https://github.com/Kite-01/server kite
cd kite
bun install
bun install --cwd client
```

</Step>

<Step title="Start Postgres">

If you don't have one, this matches the example configuration:

```sh
docker run -d --name kite-db -p 54320:5432 \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=kite postgres:18
```

</Step>

<Step title="Configure it">

Copy the example and fill it in. [Configuration](/server/configuration) explains every variable.

```sh
cp .env.example .env
```

At minimum, replace `KITE_ENCRYPTION_KEY`, `KITE_OPERATOR_MNEMONIC` and `KITE_ROOT_KEY` with your own values.

</Step>

<Step title="Create the tables">

```sh
bun run migrate
```

</Step>

<Step title="Run it">

<Tabs>

<Tab title="Development">

```sh
bun run dev
```

The API and dashboard reload as you change the code.

</Tab>

<Tab title="Production">

```sh
bun run build
bun run start
```

`build` typechecks and builds the dashboard into `client/dist`, which the server serves.

</Tab>

</Tabs>

</Step>

<Step title="Open the dashboard">

Open the URL it prints, usually `http://localhost:3000`, and sign in with your root key. Then follow [First run](/server/first-run).

</Step>

</Steps>

## Check it's up

```sh
curl -s http://localhost:3000/api/overview/info -H "x-kite-root-key: $KITE_ROOT_KEY"
```

```json
{
  "version": "1.0.0",
  "operators": [{ "chainType": "Evm", "address": "0x…" }],
  "chains": []
}
```

The operator address is the wallet that sends settlement and refund transactions. The dashboard shows it too, under the settings button. It's the address your [Kite factory](/contracts/overview#deploying-a-factory) must be deployed with as its operator.
